# 1. Product Vision

HabitBloom is a **mobile-first Progressive Web App (PWA)** inspired by the principles of *Atomic Habits*. It helps users build lasting habits by making habit tracking simple, motivating, and enjoyable.

Unlike traditional habit trackers that focus only on streaks, HabitBloom emphasizes **identity-based habits**, **tiny habits**, and **consistent progress**.

The goal is not to complete tasks.

The goal is to become the person the user wants to be.

---

# 2. Problem Statement

People start habits with motivation but fail because:

* Goals are too ambitious.
* Habit trackers become boring.
* Missing one day destroys motivation.
* Users don't understand why habits matter.
* Most apps are cluttered with unnecessary features.

HabitBloom solves this by encouraging small, sustainable actions and celebrating consistency over perfection.

---

# 3. Goals

### Primary Goals

* Build habits consistently.
* Make tracking effortless.
* Encourage identity-based growth.
* Keep users engaged without overwhelming them.

### Success Metrics

* User opens app daily.
* User completes at least one habit daily.
* Weekly completion rate increases over time.
* Users maintain habits for 30+ days.

## Habit Management

Users can:

* Create habit
* Edit habit
* Archive habit
* Delete habit

Each habit contains:

| Field           | Required |
| --------------- | -------- |
| Name            | Yes      |
| Icon            | Yes      |
| Color           | Yes      |
| Tiny Habit      | Yes      |
| Identity Goal   | Yes      |
| Why             | Optional |
| Repeat Schedule | Yes      |
| Reminder Time   | Optional |

Example

```text
Habit

Read Books

Identity

Become a Reader

Tiny Habit

Read 1 Page

Why

Knowledge compounds every day.
```

# 7. Functional Requirements

## Dashboard

### User Story

As a user

I want to immediately see today's habits

so I can quickly complete them.

Acceptance Criteria

* Loads under 2 seconds.
* Displays today's habits.
* Shows progress bar.
* Shows streak.

---

## Create Habit

Acceptance Criteria

* User enters habit details.
* Habit appears immediately.
* Data saved locally.
* Validation prevents empty names.

---

## Complete Habit

Acceptance Criteria

* One tap completion.
* Updates statistics instantly.
* Updates streak.
* Plays completion animation.

---

## Statistics

Acceptance Criteria

Automatically updates after every completion.

---

## Calendar

Acceptance Criteria

Shows completion history.

---

## Reminder

Acceptance Criteria

Browser notification appears at scheduled time (if permission is granted).

# 15. MVP Definition

The product is considered **MVP complete** when a user can:

* Create habits
* Edit habits
* Delete or archive habits
* Mark habits complete
* Track streaks
* View statistics
* Browse history in a calendar
* Receive reminders
* Read daily habit tips
* Use the app offline
* Install it as a PWA
* Export and import their data

---

# 16. Future Vision

HabitBloom should feel less like a checklist and more like a quiet companion that reinforces positive routines. Every interaction should reduce friction, encourage consistency, and remind users that missing once is a setback, not a failure. If it eventually grows into a public product, the foundation should already support scaling without requiring a complete rewrite.
